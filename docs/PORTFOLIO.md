# TripMate — 개인 포트폴리오 사이트 노출 내용

`jjssspark.github.io`의 TripMate 카드에 어떤 내용을 넣고 뺐는지 정리한 문서입니다.
개인 사이트는 "30초 후킹" 역할이고, 이 프로젝트의 깊이 있는 내용(트러블슈팅·ADR·성능 수치)은 GitHub README와 노션이 담당합니다. 세 채널에 같은 내용을 중복해서 넣지 않기 위한 기준을 남겨둡니다.

## 카드에 넣은 것

- 썸네일: `output/screenshots/01-home.jpg` — 다른 카드의 추상 캔버스 시각화 대신 실제 홈 화면 스크린샷을 사용
- 한 줄 소개: "AI가 목적지·날짜·예산·동행 유형·선호 스타일을 입력받아 Day별 여행 일정(동선·식사시간 고려)을 생성해주는 서비스"
- 담당 역할 (한 줄로 압축): "팀 프로젝트 종료 후 개인 저장소로 이전 — 인증·AI 파이프라인·배포 전 영역 단독 고도화"
- 기술 태그: React · TypeScript · Vite · Supabase · Gemini API
- 링크 3개: Repository ↗ · Demo ↗ · Notion ↗ (트러블슈팅 노션 페이지로 연결)
- 인터랙션: 기본 상태는 썸네일+한 줄 소개만 보이고, 카드에 호버하면 역할·태그·링크가 확장되어 보임

## 카드에서 뺀 것 (다른 채널이 담당)

- 응답속도(로컬 실측 12.0~19.5초), 단위 테스트 11개 통과, Lighthouse Performance 61점 → GitHub `docs/PERFORMANCE.md`
- 트러블슈팅 5건 상세(재현 조건·틀렸던 가설·검증 로그) → 노션 트러블슈팅 문서
- ADR 5건 상세(고려한 대안·근거·실제 결과) → 노션 ADR 문서
- 나머지 스크린샷 6장(02~07), 데모 영상 전체(`output/video/demo-full.mp4`) → GitHub README

## 왜 이렇게 나눴는가

개인 사이트에 성능 수치·트러블슈팅 상세까지 다 넣으면 정작 후킹이 필요한 자리에 정보 밀도만 높아져서 30초 안에 훑기 어려워진다. 사이트는 "이게 뭔지, 어떤 느낌인지"만 보여주고, 관심이 생긴 사람이 Repository·Demo·Notion 링크를 눌러 다음 단계(3분/15분)로 넘어가도록 설계했다.
