## Keep — 계속 할 것

### 판단할 때마다 이유를 남긴 것

ADR 10건, 트러블슈팅 15건을 남겼다. 덕분에 한 달 뒤 "왜 이렇게 했더라"를 추측하지 않았고, 결정을 뒤집을 때도 무엇을 뒤집는지 정확히 알았다. 실제로 모델 폴백 체인과 사진 실시간 조회 두 건을 근거를 갖고 뒤집었고, 지우는 대신 왜 뒤집었는지를 덧붙였다.

### 검증할 수 있는 걸 프롬프트에 맡기지 않은 것

"실재하는 장소만 말해줘"라고 부탁하는 방식은 지켜졌는지 확인할 방법이 없다. 그래서 AI가 뽑은 장소를 카카오 지도에 검색해 없으면 버리는 코드로 옮겼다. 중복 방지도, 제외 요청도 같은 이유로 코드가 강제한다.

### 실패를 숨기지 않기로 한 것

예전엔 AI가 실패하면 미리 만들어둔 가짜 일정이 200으로 나갔다. 화면상으로는 정상처럼 보인다. 이걸 없애고 실패를 상태 코드로 드러냈다. 대신 이유를 나눠서, 장소가 부족한 건지 AI 한도를 다 쓴 건지 사용자가 알 수 있게 했다.

## Problem — 반복된 문제

### 같은 뿌리를 네 번 다르게 고쳤다

| 시점 | 증상 | 그때 한 일 |
|---|---|---|
| 7월 13일 | 502/504 타임아웃 | thinking 모드를 껐다 |
| 직후 | 로컬만 타임아웃 | 코드 중복을 정리했다 |
| 8월 2일 | 응답이 17~25초로 흔들리고 가짜 일정이 나감 | 타임아웃 예산을 다시 나눴다 |
| 8월 16일 | 무료 한도 소진으로 생성 전체 실패 | 호출 횟수 자체를 줄였다 |

셋 다 맞는 수정이었지만 전부 같은 층위의 대증요법이었다. 네 번째에 와서야 "요청 하나가 AI 호출 4번에 묶여 있다"는 위층을 봤다.

### 실패 경로를 나중에 붙였다

성공 경로는 처음부터 설계했는데 실패 경로는 사고가 날 때마다 붙였다. 폴백도, 타임아웃도, 한도 소진도 그랬다. 그러다 보니 폴백이 사고를 숨기는 역할을 하게 됐다.

### 검증 안 한 코드를 그대로 옮겼다

계획서에 적어둔 정규식을 실제 값으로 안 돌려보고 옮겼는데, 한글을 전부 지우는 코드였다. 그대로 나갔으면 모든 한국 장소가 같은 이름으로 묶였다. 배포 전에 잡아서 사고는 안 났지만 운이 좋았던 거다.

## Try — 바꾼 행동과 결과

### 상수를 정하기 전에 실측부터 한다

전에는 "30초 안에 끝내야 하니까 8 + 5 + 10초"처럼 상한에서 역산해 나눴다. 실제 응답이 얼마나 걸리는지는 안 봤고, 그래서 후보 추출이 4번 중 3번 실패했다.

지금은 구간별 지연을 재고 그 값으로 예산을 잡는다. 재시도도 "이 실패가 다시 걸면 나아지는 종류인가"를 따져서, 타임아웃과 한도 초과는 재시도 대상에서 뺐다. 그 결과 1차 시도 예산이 8초에서 14초로 늘었고 후보 추출 실패가 없어졌다.

### 외부 API는 호출 횟수를 먼저 예산으로 잡는다

무료 한도가 하루 20회인 걸 알고도 호출 수를 설계에 안 넣었다. 그래서 일정 5건이면 서비스가 멈췄다.

설명 생성을 일차별에서 여행 전체 1회로 묶어 건당 4회를 2회로 줄였고, 후보 추출과 설명이 서로 다른 모델을 쓰게 나눠서 한쪽이 바닥나도 다른 쪽은 살아 있게 했다. 하루 처리량이 5건에서 20건이 됐다. 한도가 모델별로 잡혀서 두 모델을 쓰면 각각 20회씩이다.

### 고친 것은 테스트로 고정한다

7월에는 테스트가 11개뿐이라 매번 브라우저로 직접 확인했다. 그러다 AI 한도가 소진되면 확인할 방법 자체가 없어졌다.

지금은 버그를 고칠 때 테스트를 같이 쓰고, 그 테스트가 진짜 버그를 잡는지 확인하려고 고치기 전 코드로 되돌려 먼저 실패하는 걸 본다. 테스트가 251개가 되면서 한도가 소진된 날에도 검증이 막히지 않는다.

## 11월 8일 — 두 달 반 만에 다시 열어 보니

8월 19일 이후 손을 안 댔다. 11월에 포트폴리오를 다듬으려고 배포 데모를 열었더니 지도가 전부 회색이었다. 코드는 그대로인데 타일 서버(CARTO)가 키 없는 접근을 막은 것이다(TS-034). 그날 한 일은 넷이다.

- 지도 타일을 OpenStreetMap 공식 타일로 바꿨다(ADR-10)
- `npm run lint`가 설정 버그로 두 달 넘게 죽어 있었다는 걸 알았다(TS-035). 고치고, any 37곳을 전부 타입으로 바꾼 뒤 규칙을 error로 올렸다
- 800줄을 넘던 화면 컴포넌트 둘을 역할별로 나눴다
- 로컬 샌드박스에서 쟀던 Lighthouse를 배포 URL 기준으로 다시 쟀다(랜딩 데스크톱 61 → 80)

배운 건 하나다. 안 건드린 코드도 멈춰 있지 않다. 외부 무료 서비스에 기대는 부분은 날짜와 조건을 적어 두고, 가끔 배포본을 직접 열어 봐야 한다. 커밋 하나는 병렬 작업 중에 섞여 들어가 빌드가 안 되는 상태로 올라갔다(TS-036). 급하게 할수록 커밋 직전 확인은 더 천천히 해야 한다는 걸 다시 배웠다.
