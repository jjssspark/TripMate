## 2026-08 측정 — 로컬 샌드박스 기준 (비교용)

### 측정 환경

- 프로덕션 빌드(`npm run build`)를 로컬에서 `node dist/server.cjs`로 직접 실행해 측정했습니다. 실제 배포된 Netlify URL이 아니라 로컬 환경입니다.
- Lighthouse는 샌드박스 컨테이너 안에서 headless Chrome으로 실행했습니다. 일반 개발 머신이나 실제 사용자 기기보다 CPU 자원이 제한적일 수 있어, 특히 모바일 쓰로틀링 수치는 실제보다 나쁘게 나올 가능성이 있습니다. 아래에 데스크톱/모바일 두 프리셋을 함께 남기고 이 차이를 그대로 기록합니다.
- 측정 시각: 2026-08-03. Gemini 응답 시간은 그날그날 API 상태에 따라 달라질 수 있습니다.
- 최종 포트폴리오용 수치는 실제 배포 URL과 일반 개발 머신(또는 실기기)에서 재측정하는 것을 권장합니다.

## AI 일정 생성 응답 시간 — 현재 파이프라인

서버 예산은 25초입니다(`server/itinerary/runner.ts`의 `TOTAL_BUDGET_MS`). 클라이언트 타임아웃 30초는 그대로입니다.

2026-08-17 로컬 실측입니다. 표본이 적어 참고치입니다.

| 구간 | 측정값 | 조건 |
|---|---|---|
| 파이프라인 전체 (부산 2박3일) | 7.2s | 후보 추출 2.9s + 나머지. 설명 3일차 중 2일차가 쿼터 소진으로 폴백 |
| 설명 배치 호출 1회 (3일치) | 4.6s | `gemini-2.5-flash-lite`로 모델만 교체해 측정 |
| 쿼터 소진 시 실패 응답 | 0.55s | 25초 예산을 태우지 않고 즉시 429 반환 |

구 파이프라인 대비 빨라진 이유는 Gemini 호출이 줄었기 때문입니다. 이전에는 일정 전체를 한 번에 받아 오래 걸렸고, 현재는 후보 추출 1회 + 설명 1회로 나뉘되 그 사이 단계(실재 검증·날짜 배정·순서 결정·시각 배치)는 코드가 처리해 네트워크 대기가 없습니다.

Gemini 호출 횟수는 일정 1건당 2회인데 후보 추출(`flash`)과 설명(`flash-lite`)이 다른 모델이라 한도 버킷이 따로 잡힙니다. 모델당 하루 20회이므로 하루 20건이 상한입니다. (이전 판은 10건으로 적었는데 두 호출이 같은 버킷을 쓴다고 잘못 계산한 것입니다. 2026-11-08 정정)
