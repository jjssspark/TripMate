주요 기술 의사결정

ADR-6 · 신뢰도

AI 단일 호출을 6단계 파이프라인으로 분리

배경
중복 · 동선 · 실재하는 상호명을 전부 프롬프트 문장으로만 부탁하고 검증하는 코드가 없었음. 모델이 지키면 지켜지고 아니면 그대로 노출.
결정
후보 제안(AI) → 실재 검증(Kakao) → 날짜 배정 → 순서 결정 → 시각 배치 → 설명(AI). 실패 시 가짜 일정을 내보내던 폴백 제거.
근거
프롬프트 강화는 지켜졌는지 확인이 불가. 재요청 방식은 호출 수가 늘어 무료 한도(하루 20회)를 감당하지 못함.
결과
응답 16.2초 → 7.2초. 중간 단계가 전부 코드라 네트워크 대기 없음. 실패는 422 / 429로 구분해 노출.
ADR-7 · 재현성

날짜 배정 · 순서 결정을 결정적 알고리즘으로

배경
가까운 곳끼리 묶어 날짜를 나누고, 하루 안 방문 순서를 정해야 함.
결정
하루 정원을 건 k-means로 배정, 하루 8곳 이하는 완전탐색으로 최단 경로 확정(초과 시 근사). 시드는 난수 대신 최원점 선택.
근거
일반 k-means는 개수를 안 맞춰 하루 12곳 · 다른 날 2곳이 발생. 정원이 8이라 완전탐색 비용이 낮아 근사를 쓸 이유가 없음.
결과
같은 조건이면 항상 같은 일정. 알고리즘 회귀 테스트를 픽스처로 고정 가능.
ADR-8 · 호출 예산

설명 호출 배치화 + 모델 분리

배경
설명을 일차별로 호출해 3일 일정에 4회 소모. 무료 한도가 모델당 하루 20회라 일정 5건이면 소진.
결정
여행 전체 설명을 1회 배치 호출로 통합(건당 4회 → 2회). 설명만 Flash-Lite로 분리.
근거
4일치를 Flash로 받으면 14초 예산에 걸침(실측 13,970ms). 한도가 모델별로 잡혀 버킷이 분리됨.
결과
하루 처리량 5건 → 10건. 3일치 설명 1회 호출 4.6초. 검증은 일차별로 유지해 어긋난 일차만 강등.

주요 장애 대응

한도 소진 · 오분류

무료 한도를 건당 4회씩 소모, 429를 500으로 안내

증상
“조건을 바꿔 다시 시도해 주세요” 안내와 함께 생성 실패. 조건을 바꿔도 계속 실패.
원인
파이프라인이 일정 1건에 AI를 4회 호출해 하루 20회 한도를 5건 만에 소진. 429가 500으로 뭉뚱그려져 사용자가 할 수 없는 조치를 안내. 재시도 로직이 429를 즉시 재호출해 남은 한도를 추가 소모.
조치
설명 호출을 배치로 묶어 4회 → 2회. 429 전용 에러로 분리하고 리셋 시각을 한국시간으로 환산해 안내(서머타임 반영). 타임아웃 · 쿼터는 재시도 대상에서 제외.
결과
한도 소진 시 25초 예산을 태우지 않고 0.55초에 429 반환.
로컬 정상 · 배포만 실패

배포본만 생성 500 — 환경변수 누락

증상
로컬은 정상, 배포 데모만 500. 응답이 1.36초에 반환 — 서버 예산 25초의 근처에도 못 감.
진단
키 이름 불일치와 함수 타임아웃을 차례로 의심했으나 모두 반증. 1.36초라는 응답 시간이 “느린 단계에 도달조차 못 했다”는 근거였음.
원인
Netlify에 KAKAO_REST_API_KEY 미등록. 실재 검증 통과 장소가 0건이 되어 이후 단계 진행 불가. 파이프라인 교체로 새 필수 의존성이 생겼는데 배포 환경에 미반영.
시사점
실패 응답에서도 소요 시간이 진단 정보. 에러 문구(“잠시 후 다시”)가 원인을 가릴 수 있음.
배포 전 차단 · 무증상

정규식이 한글을 전부 제거

증상
중복 제거용 이름 정규화가 한글 입력을 빈 문자열로 반환. 에러 없음. 영문 입력으로는 정상 동작해 드러나지 않음.
원인
\W는 ASCII 기준 정의라 한글을 단어 문자로 보지 않음. u 플래그로도 확장되지 않음. 그대로 배포됐다면 모든 한국 장소가 동일 키로 묶여 하루 1곳만 남음.
조치
제거 대상 열거 대신 남길 대상 지정([^\p{L}\p{N}]). 괄호 표기 혼재 문제까지 함께 해소.
시사점
계획서에 적힌 코드가 검증된 코드는 아님. 옮기기 전에 실제 값으로 1회 실행.
